# Онлайн-деканат

Локальный сервис предварительной проверки студенческих документов. Пользователь загружает фото или PDF, задаёт вопрос и получает извлечённые сведения, результат проверки комплектности и ссылку на пункт Положения или фрагмент документа.

Проект реализован для кейса «Онлайн-деканат». В рабочем профиле используются материалы учебного университета «Меридиан» из официального пакета участников: 30 документов, 120 вопросов и контракт `results.json`. Решение о принятии документа остаётся за сотрудником деканата.

## Публичная демонстрация

Открыть готовую версию: [online-dean-demo.onrender.com](https://online-dean-demo.onrender.com/).

На публичном хосте включён безопасный демонстрационный режим: доступны подготовленные примеры из пакета кейса, а загрузка личных документов и импорт Положения отключены. Для показа пройдите сценарий «Академический отпуск»: он демонстрирует распознавание, паспорт результата, источники, черновик обращения и путь документа к сотруднику.

## Что умеет сервис

- Принимает JPG, PNG и PDF до 15 МБ; PDF обрабатывается постранично.
- Распознаёт три типа документов: справку об обучении, заявление на академический отпуск и справку о практике.
- Исправляет ориентацию, наклон и неравномерное освещение до распознавания.
- Извлекает значения с координатами, поэтому пользователь может увидеть исходный фрагмент на странице.
- Проверяет обязательные поля по подключённому Положению и возвращает точные пункты-основания.
- Позволяет вручную исправить поле с сохранением истории проверки.
- Выгружает протокол, JSON и пакет доказательств с контрольными суммами.
- Работает локально: документы не передаются в сетевые сервисы.

## Быстрый запуск

Требования: Python 3.12+, Tesseract 5.x с языками `rus` и `eng`.

```powershell
.\start.ps1
```

После запуска открыть http://127.0.0.1:8000. Проверка готовности: http://127.0.0.1:8000/api/ready.

### Установка с нуля на Windows

```powershell
winget install --id UB-Mannheim.TesseractOCR --exact
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
New-Item -ItemType Directory -Force .runtime/tessdata
Invoke-WebRequest https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/rus.traineddata -OutFile .runtime/tessdata/rus.traineddata
Invoke-WebRequest https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/eng.traineddata -OutFile .runtime/tessdata/eng.traineddata
.\start.ps1
```

Первичная установка использует сеть только для получения зависимостей и языковых данных Tesseract. Дальнейшая обработка документов выполняется локально. Пути можно задать через `TESSERACT_CMD`, `TESSDATA_DIR` и `DEAN_CONFIG_DIR`.

Для Linux установить пакеты `tesseract-ocr`, `tesseract-ocr-rus`, `tesseract-ocr-eng`, создать виртуальное окружение и запустить `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`.

## Архитектура

```text
браузер
  │ загрузка документа и вопрос
  ▼
FastAPI ── сессия в памяти ── экспорт протокола
  │
  ├─ OCR: raster/Pillow → OpenCV → Tesseract
  ├─ классификация: маркеры и заголовки документа
  ├─ извлечение: поля, даты, периоды, координаты источника
  ├─ визуальные отметки: подпись и печать
  └─ правила: комплектность, ответ и ссылки на пункты
```

Подробности компонентов, форматов и границ описаны в [docs/architecture.md](docs/architecture.md). Операционные сценарии — в [docs/operations.md](docs/operations.md), решения по интерфейсу и лицензиям — в [docs/design.md](docs/design.md).

План разделения ролей и внедрения после демо — в [docs/roadmap.md](docs/roadmap.md). Конфигурация и инструкция для публичной безопасной демонстрации — в [docs/public-demo.md](docs/public-demo.md).

Бонус «новый тип документа через конфиг» можно показать на готовом профиле «Пропуск студента»: [инструкция и команда проверки](docs/custom-profile.md).

## Технологический стек

| Область | Технологии | Роль |
| --- | --- | --- |
| Backend | Python 3.12, FastAPI, Uvicorn, Pydantic | HTTP API, валидация данных, сессии и экспорт. |
| OCR и документы | Tesseract, pytesseract, Pillow, pypdfium2 | Распознавание русского и английского текста, обработка изображений и PDF. |
| Обработка изображений | OpenCV | Ориентация, наклон, освещение и визуальные признаки отметок. |
| Правила и данные | JSON, локальный поиск по пунктам | Схемы документов, проверка комплектности и источники ответа. |
| Клиент | HTML, CSS, JavaScript без CDN | Загрузка, просмотр результата, подсветка доказательств и экспорт. |
| Поставка | Docker Compose, PowerShell, SHA-256 | Локальный запуск, healthcheck и контроль целостности пакета. |
| Тестирование | pytest, FastAPI TestClient | Регрессии извлечения, API, правил и экспорта. |

## API

Интерактивное описание доступно по адресу `/docs` после запуска. Основные методы:

| Метод | Назначение |
| --- | --- |
| `GET /api/ready` | Готовность сервиса и OCR. |
| `GET /api/config` | Активные схемы и правила. |
| `POST /api/analyze` | Анализ загруженного документа. |
| `POST /api/review/{id}` | Вопрос по сессии или ручное исправление поля. |
| `GET /api/compare/{before}/{after}` | Сравнение исправленной версии с предыдущей. |
| `GET /api/appeal/{id}` | Черновик обращения или памятка по доработке на основе результата. |
| `POST /api/decision/{id}` | Решение сотрудника с обязательным основанием. |
| `GET /api/queue` | Минимальная очередь сотрудника без изображений и OCR-текста. |
| `POST /api/knowledge` | Подключение пользовательского Положения. |
| `POST /api/dossiers` | Создание сводной проверки из уже проанализированных документов. |
| `POST /api/dossiers/{id}/resolve` | Фиксация решения сотрудника по расхождению. |
| `GET /api/dossiers/{id}/export` | JSON-сводка досье с источниками и решениями. |
| `GET /api/export/{id}/redacted` | Обезличенная JSON-копия для безопасной демонстрации результата. |
| `GET /api/report/{id}` | Печатный протокол. |
| `GET /api/bundle/{id}` | Пакет доказательств. |

## Официальный batch

Команда ниже создаёт файл, совместимый с контрактом из пакета участников. Скрипт читает только manifest документов и вопросов; эталонные результаты не участвуют в распознавании.

```powershell
.\.venv\Scripts\python.exe -m scripts.official_batch --package official/participants-v1 --output results.json
.\.venv\Scripts\python.exe official/participants-v1/evaluate.py --reference official/participants-v1/reference_results.json --predictions results.json --report output/official/evaluation.json
```

На открытом пакете получены: 30 документов, 120 вопросов, `field_accuracy_macro = 1.0`, `validation_exact_match = 1.0`, `question_exact_match = 1.0`. Это результат на открытых данных и не заменяет проверку организаторов на закрытом наборе.

Формат результата: текстовое отсутствие — `не найдено`, подпись и печать — `boolean`, даты — ISO 8601. Для неподдержанного вопроса возвращаются `answerable=false`, `value=null`, `sources=[]`.

## Безопасность и хранение

- Сервер принимает запросы только с `localhost`.
- Внешние запросы, CDN и постоянное хранилище документов не используются.
- Сессии, подключённые правила и досье существуют в памяти 30 минут неактивности; лимит — 12 сессий документов, 8 баз правил и 8 досье.
- Для демонстрации доступна отдельная обезличенная JSON-выгрузка: без изображений, OCR-текста, координат и прямых идентификаторов.
- В экспортный пакет не попадает исходный загруженный файл. Включаются обработанные страницы, результаты и SHA-256 манифест.
- Пакет доказательств не является электронной подписью и не подтверждает подлинность документа.

Docker-конфигурация подготовлена в `compose.yaml`: непривилегированный пользователь, read-only файловая система, временный каталог и healthcheck. В текущем окружении Docker Engine недоступен, поэтому контейнерный запуск отдельно не подтверждён.

## Ограничения

Сервис предназначен для печатных документов близких к поддерживаемым макетам. Наличие подписи или печати определяется как визуальный признак, а не как подтверждение подлинности. Рукописные записи, произвольные макеты и качество снимков вне проверенных сценариев требуют ручной проверки.
