# Бонус: новый тип документа через конфиг

Сервис не требует изменения Python-кода для добавления нового типа в обычный, не конкурсный профиль. Схема полей и правила хранятся отдельно в `documents.json` и `rules.json`. При запуске система проверяет ссылки из правил на существующие поля, а валидатор отдельно проверяет структуру схемы.

## Готовый пример

В `examples/student-pass-profile/` находится минимальный профиль с новым типом `student_pass` — «Пропуск студента». В нём описаны маркеры, четыре поля и пункт правила комплектности.

Проверка профиля:

```powershell
.\.venv\Scripts\python.exe -m scripts.validate_profile examples\student-pass-profile
```

Ожидаемый результат содержит `"valid": true` и `"student_pass"` в списке типов.

Запуск сервиса с этим профилем:

```powershell
$env:DEAN_CONFIG_DIR = "$PWD\examples\student-pass-profile"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

После запуска новый тип появляется в списке типов документа и участвует в классификации, извлечении полей, проверке комплектности и ответах со ссылкой на правило.

## Граница конкурсного профиля

Профиль «Меридиан» фиксирован условиями кейса и использует отдельный контракт результатов. Его намеренно не изменяют: пример нужен для демонстрации расширяемости продукта, а не для подмены обязательных трёх типов документов.
