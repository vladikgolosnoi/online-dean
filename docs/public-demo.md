# Публичная демонстрация

## Подготовка

В корне проекта добавлен `render.yaml`. Он описывает бесплатный Docker Web Service на Render и включает безопасный демонстрационный режим через переменную `DEAN_PUBLIC_DEMO=true`.

В этом режиме доступны встроенные примеры документов. Загрузка файлов и импорт Положения отключаются в интерфейсе и на API-уровне. Это позволяет дать ссылку жюри, не превращая демонстрационный контур в приёмник персональных данных.

## Публикация после финализации

1. Создать пустой репозиторий на GitHub и загрузить в него проект без `.venv`, `output/`, `.runtime` и исходных личных документов.
2. В Render выбрать **New → Blueprint** и подключить репозиторий. Платформа прочитает `render.yaml`.
3. Подтвердить сервис `online-dean-demo`, план `free` и дождаться статуса Live.
4. Открыть публичный адрес `*.onrender.com`, проверить `/api/ready` и каждый из трёх встроенных примеров.
5. Скопировать адрес в презентацию и README после приёмки.

## Что нужно знать о бесплатном контуре

Render поддерживает бесплатные Web Service для динамических Python/FastAPI-приложений, выдаёт публичный `onrender.com`-адрес и может разворачивать сервис из связанного Git-репозитория. Бесплатный сервис останавливается после 15 минут без входящих запросов, а первый запрос после остановки может запускать его около минуты. Локальная файловая система такого сервиса временная, поэтому сервис не хранит документы и сессии между перезапусками. Для демонстрации это согласуется с текущей архитектурой в памяти. [Документация Render: Free](https://render.com/docs/free), [Web Services](https://render.com/docs/web-services).

## Проверка до публикации

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --check web\app.js
docker build -t online-dean-demo .
docker run --rm -p 8000:8000 -e DEAN_PUBLIC_DEMO=true online-dean-demo
```

Затем открыть `http://127.0.0.1:8000`, убедиться, что виден баннер публичного демо, а встроенные примеры запускаются. Запрос на `/api/analyze` должен возвращать 403.
