# План развития после демо

Этот документ разделяет готовый локальный продукт, публичную демонстрацию и функции для рабочего внедрения.

## Ближайший этап: публичное демо

Цель — дать жюри и участникам ссылку, по которой можно проверить сервис без установки.

- Развернуть Docker-образ как публичный demo-сервис.
- Включить `DEAN_PUBLIC_DEMO=true`: доступны подготовленные примеры, а загрузка личных документов и импорт Положения отключены.
- Оставить досье, маршрут обработки, объяснения правил, экспорт и обезличенную выгрузку доступными для исследования.
- После финальной проверки опубликовать репозиторий и подключить автоматическое обновление по основной ветке.

Публичный режим предназначен для демонстрации возможностей. Рабочие документы нужно обрабатывать в локальном контуре до появления авторизации и политики хранения.

## Следующий продуктовый этап: роли и кабинет сотрудника

### Студент

- подаёт документ и видит только собственный статус;
- получает конкретный запрос на дополнение без доступа к внутренним проверкам других студентов;
- загружает новую версию по защищённой ссылке или после входа.

### Сотрудник деканата

- работает с очередью: «новые», «нужна сверка», «нужно дополнение», «готово к решению»;
- сверяет поля, подтверждает расхождения в досье и фиксирует итоговое решение;
- видит журнал действий только по назначенным обращениям.

### Администратор

- управляет учётными записями и ролями;
- подключает и версионирует Положения, схемы документов и шаблоны уведомлений;
- просматривает аудит, метрики качества OCR и правила хранения данных.

## Технические условия перед рабочим внедрением

1. Вход через корпоративный провайдер, разграничение прав и журнал аудита.
2. Постоянное изолированное хранилище документов с политикой удаления и резервным копированием.
3. Очередь задач OCR вместо памяти одного процесса.
4. Уведомления студенту и сотруднику, интеграция с информационной системой вуза.
5. Нагрузочное тестирование, мониторинг и регламент реагирования на ошибки.
